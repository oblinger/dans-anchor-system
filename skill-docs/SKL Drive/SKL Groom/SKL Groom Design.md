`/groom`'s design is **shared with `/query`** — the two are one **resolution layer** (groom plans the backlog frontier; query consolidates the irreducible residue into the asking surface), so their design lives in a single PRD rather than two that drift.

## Where the design lives

- **[[Query PRD]]** — **the design home. Start here.** The shared resolution-layer PRD for both `/groom` and `/query`: groom's three activities (work-item identity, the executable frontier, grooming the frontier), the `F` / `T` / `M` / `R` identity model, the five groomed states, the question bar, and how triage / groom / query compose into one autonomous machine. (Named "Query PRD" for link stability; read it as the resolution-layer PRD.)
- **[[facets/FCT Track/Backlog\|FCT Backlog]]** — the **facet**: what a valid `{NAME} Backlog.md` must look like — the `R-backlog` ruleset (numbering, frontier invariants) and the **five groomed states → body-contract → rule** table groom drives every frontier row into.
- **[[skills/workflow/SKILL.md\|workflow — the state graph]]** — the canonical **state graph**: every bracket, the Definition of Ready, the Blocked / Waiting / Watching semantics, and the transitions groom applies.
- **[[FCT Query]]** — the `R-query` ruleset for the `{NAME} queries.md` surface groom parks its residual questions into.
- **[[skills/groom/SKILL.md\|SKILL]]** — the `/groom` **runbook** (the procedure the skill follows, not the design rationale).
