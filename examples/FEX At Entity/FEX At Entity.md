# FEX At Entity
The worked instance for [[DAS At Entity]] — a fictional advisor, in folder form, carrying all three containers at once so the routing rule can be read off a real tree rather than a description of one.

**Marguerite Vale is not a real person.** Everything below her is a faithful instance of the facet, not a description of it; read the files, not this page.

```
FEX At Entity/
└── @Marguerite Vale/
    ├── @Marguerite Vale.md                        identity line · INFO · # LOG
    ├── Drafted/
    │   ├── 2026-06-02 — Intro ask to Hollis.md    one thread, two exchanges, v1→v2
    │   └── 2026-07-28 — Q3 rate change.md         one thread, sent and verified
    └── Meet/
        └── 2026-06-11 — Intro call.md             prep + contemporaneous + after-notes
```

**What each file is there to show.**

- **[[@Marguerite Vale]]** — the `# LOG` keeps five events and every one of them is a *relationship or status* note. This is the 54% the facet says does not move; if the log looked empty here the example would be teaching the wrong thing.
- **[[2026-06-02 — Intro ask to Hollis]]** — the drafting unit. Two exchanges live in **one** document with the newest on top, and the superseded v1 is kept as text rather than as commentary about text.
- **[[2026-07-28 — Q3 rate change]]** — the same shape after sending. `Sent 2026-07-29` replaced `Draft`, and the file did **not** move: `Drafted/` names provenance, so a sent message stays put.
- **[[2026-06-11 — Intro call]]** — one meeting, three time-slices (prepared before, written during, added after), one document. It is filed under Marguerite because the call was hers.

**The near-miss worth reading.** The `# LOG` entry `2026-07-14  Reply to her scheduling note` is correspondence that stayed in the log, because nothing was drafted for it — a two-line reply typed in the mail client. The migration selector is *"was this a drafting session?"*, not *"is this about email"*, and this is the entry that separates the two.
