# Warden Consumers
The inventory of things that consume agent moments through the Warden substrate — what each is, which moments it binds, and what it demands of the engine. Drafted 2026-07-01 as the starting material for the [[F131 — Hooks — fast inner-loop check substrate (path-rule alerts first)|F131]] Q4 parley; **confirmed by the user the same day** (F131 Q4 resolution): the confident set is the starting set — the substrate is designed against it — extended by the rules-corpus scan in § The rules corpus below.

**Why this doc exists.** The substrate (binary structure, config format, action vocabulary, matching) must be designed against the full range of consumers, not just the first one — otherwise path-rule-specific assumptions get baked in. Every consumer below reduces to the same skeleton: *bind moments (F209 taxonomy) → match/guard (F210 conjunction; F131 unification bindings) → act (steer / deny / fix / record)*. What varies is which moments, how expensive the guard is, and which action.

> **User reactions recorded 2026-07-01** — the buckets below are updated per the user's item-by-item review (chat). Movements: **conversation-content gating → Confident** ("quite important"); **maintain → Warden-native**; **spec-conformance → explicitly first-class** under doc-audit; **anchor-invariant validation → fits-in-scope**; **secret detection → no special support**; **replay log → leveled debug logging**; **file-size sanity → an environment property, not a consumer**. The language extensions these imply are drafted (marked *(proposed)*) in [[Warden Semantics]] § The interpretation environment.

## Confident — exist today as bespoke hooks or ratified designs; they WILL ride the substrate

- **path-rule alerts** — deny/warn when Edit/Write touches a state-managed region (backlog rows, queries.md, TOC tables). The F131 motivator. Moments: `tool:pre:Edit/Write`. Demands: path-pattern unification with variable bindings; sub-ms match; veto action.
- **conversation-content gating** — rules that fire on what the agent (or user) *said*: a cheap telltale-sign regex over the turn's text gates an author-written steer, so the agent is bothered **only when the content shows evidence it's going wrong** ("never ask the user a question like this when …"). Promoted from Uncertain by the user 2026-07-01: *"quite important."* The [[F217 — Conversation-content gating — rules on what was said|F217]] `turn` view is the designed realization — `turn.agent_said` is the lazily-computed last-response string the user sketched as `agent.response` (alias *(proposed)* in [[Warden Semantics]]), `turn.user_said` makes user content available, and the prefilter discipline is exactly the gate-before-tell economy. Moments: `prompt:stop` (mid-turn moments later). Demands: lazy transcript-tail view; regex-class guards on the steer path; once-per-`(rule, turn)` loop wall.
- **doc-audit on write** — run the rule engine against a written markdown file; auto-fix mechanical findings, steer the rest into context. Exists as `audit-on-write.sh` (F177); M4 migrates it onto the compiler. Moments: `write:markdown`. Demands: full ruleset evaluation, fix-capable actions, per-file scoping.
- **advice injectors** — classify a known failure signature in a tool result and inject the matching fix into the next turn. Exists as the F181 webfetch-authwall hook; the pattern generalizes (Bash 999, gh auth, MCP token expiry). Moments: `tool:post:<tool>`. Demands: cheap classifier guards; steer (additionalContext) action; one-bundle-per-failure-mode packaging.
- **command guard** — veto dangerous shell commands before they run (`bash-guard.sh` today; the `tool:pre` deny semantics were ratified in [[F210 — Conjunction binding + indexing|F210]] § Resolved). Moments: `tool:pre:Bash`. Demands: veto with reason; the `aow-safety` floor; near-zero latency.
- **maintain — Warden-native** — keep derived files in sync with their sources (`maintain-hook.sh` today: mtime triggers + `:pr`/`:commit`/`:daily` events). Upgraded per the user 2026-07-01: Warden already watches every edit, so **maintenance is a function of Warden itself**, not an external consumer riding it — and maintain rules are **ordinary rules** (nothing official marks them "maintain"; that's just what they do). The language needs no new verbs: `when:: write:*` / `git:*` / timer moments + a staleness test over file stat members (*(proposed)* `.mtime`/`.size` in [[Warden Semantics]]) + a `sh(argv)`/`edit` body. Moments: `write:*`, `git:*`, timers. Demands: event moments beyond tool calls; stat-class file members.
- **agent-state sensing** — the [[F216 — Agent-state model — sensing what the agent is doing|F216]] classifier consuming the moment ledger to maintain `agent.state` / `agent.skill`. Moments: all (it IS the ledger's standing consumer). Demands: ordered, timestamped moment stream; session registry.
- **queue hygiene autofire** — audit-q's banner refresh + stale-bracket detection fired on backlog/queries writes rather than manual runs (an M4 migration target). Moments: `write:markdown` scoped to Track files. Demands: same as doc-audit, narrower scope.

## Reshaped by the 2026-07-01 review — engine facilities and properties, not consumers

- **observability → leveled debug logging** — the user wants a **turn-up-able audit trail**, not always-on durable history: a simple leveled logger (error/warn/info/debug/trace) on the engine, where trace shows every moment, every candidate rule, and why each did or didn't fire. Off (or low) by default — nothing logs everything all the time; you raise the level when debugging rule behavior. Implementation note: `oblog` is the Rust leveled logger in ob-utils, so the Rust engine (F213) can use it natively; the Python reference (F212) uses a plain stdlib logger — do **not** vendor oblog into skills. *(proposed engine config: `WARDEN_LOG` level, [[Warden Runtime]].)*
- **file-size sanity → an environment property** — not a consumer and not a shipped rule: the read's *target metadata* should simply be **available in the language** ("we can do other things with it besides warn"). *(proposed)* `event.target` — the tool call's file target as a lazy stat view (`.path`, `.size`, `.mtime`, `.exists`, no content read) — plus stat members on `file`; see [[Warden Semantics]]. Anyone who wants the enormous-read warning writes it as a one-line rule.
- **spec-conformance checks — first-class under doc-audit** — structurally still rulesets the **doc-audit on write** consumer evaluates (no double-count), but the user emphasized these are **definitely in scope and important**: the agent must learn it formatted a document wrong *at the write*, not at the next `/audit` sweep — malformed docs must never persist in the file system. Regex and structural checks over the document are exactly the `checked`-rule surface that already exists.

## Uncertain — plausible; shape or value still open

- **secret detection** — deny tool calls that would expose keys/tokens. User 2026-07-01: **very specialized — build nothing special for it.** If the general language happens to express it trivially (a command-guard-class rule), fine; it places zero demands on the substrate design.
- **trigger-discipline integration** — wiring F091-style compact/markdown-write triggers through the substrate instead of bespoke hook scripts. Almost certainly right eventually (it's M4's spirit); uncertain whether F091's surface survives as its own consumer or dissolves into doc-audit + maintain.
- **anchor-invariant validation** — slug uniqueness, `.anchor` structure, dispatch coverage. Moved up from "shouldn't" per the user 2026-07-01: it **should fit in scope** even if it's never a priority — e.g. `when:: write:markdown` + a `sh(["ha", …])` uniqueness lookup in the body is already expressible (cross-vault reads are audit-passive per [[Warden Semantics]] § `anchor`). Nothing new to build; periodic `/audit structure` remains the primary home.

## Off the substrate

- **session-state dashboard** — a UI that *reads* what agent-state sensing maintains; it consumes the ledger's output, not moments, so it sits above the substrate, not on it. But the user's underlying want IS a substrate demand: **many rules condition on agent state**, so `agent.*` should carry a **pretty complete set of lazily-computed state properties** — lazy because they cost computation and resources; most rules touch none. Starter-set proposal *(proposed)* in [[Warden Semantics]] § `agent`; the standing requirement is recorded on [[F216 — Agent-state model — sensing what the agent is doing|F216]].

## The rules corpus — the workload behind doc-audit (Q4 extension, scanned 2026-07-01)

Per the user's Q4 ruling, the consumer inventory is extended by what the vault actually carries in Decisions and Rulesets:

- **115 `# RULESET` blocks ≈ 482 rules** — 254 `checked` / 109 `stated` / 82 `sampled` / 3 `tracked` — in ob-skills facets (~49 files), `library/Rulesets/` (~44), disciplines, and examples; every block scoped by `where::` (always / file / anchor / sentinel kinds, `{ANCHOR}`/`{NAME}` pattern variables).
- **22 live `## Decisions` surfaces** vault-wide — documentation only per the [[FCT Decisions]] doctrine (Warden never computes against decisions); they place no demand on the engine beyond confirming rulesets as the sole computable surface.

Consequences for the substrate: applicable-ruleset resolution must be an **indexed table probe** (compile the corpus, keyed by source mtimes — the `/distill` direction), not a per-moment scan; the **kind split is structural** — checked rules are engine-evaluable, stated/sampled can only be *steered* into agent context as reminders, tracked feed the ledger; and covering the confident seven + most of this corpus is the ratified "really good starting set." Full design: [[F131 — Hooks — fast inner-loop check substrate (path-rule alerts first)|F131]] § Substrate scope.

## What the inventory implies for the substrate

The confident eight exercise the full action vocabulary (veto / steer / fix / record / run-recipe), both `pre` and `post` phases, path unification with bindings, transcript-content guards, event moments beyond tool calls, and one standing stream consumer. If the substrate serves those eight cleanly, everything in the uncertain bucket is a configuration, not a redesign. The 2026-07-01 review closed the inventory question (F131 Q4) and converted the residue into **language-surface proposals** — the *(proposed)* blocks in [[Warden Semantics]] (`agent.*` property set, `event.target` + file stat members, the `agent.response` alias) and [[Warden Runtime]] (leveled logging) — for joint review.
