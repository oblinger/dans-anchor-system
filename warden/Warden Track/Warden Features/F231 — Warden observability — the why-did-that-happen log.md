# F231 — Warden observability — the why-did-that-happen log

Commissioned by the user 2026-07-06 (at the arch/adoption review): *"I'm gonna see the system behave in a way that I didn't expect, but I'm not gonna even know what warnings were generated by the rules system, what actions were taken. So I won't know if the LLM didn't do the right thing or we didn't tell it the right thing."*

**The goal** (now a [[Warden PRD]] § Goals entry): **the user and the agent can look back and understand why something happened the way it did** — and what information Warden must surface for that purpose.

## The failure mode this closes

Warden is invisible by design (fail-open, non-blocking, steers folded into agent context). That same invisibility means a misbehavior has four indistinguishable causes today:

1. **No rule fired** (not adopted here / wrong moment / `where::` didn't match) — nothing was ever said.
2. **A rule fired but said the wrong thing** — the steer text was misleading or stale.
3. **The rule fired correctly and the agent ignored it** — an LLM-compliance failure, not an engine one.
4. **The fire was suppressed** — kill switch, once-per-turn dedup, re-eval throttle, over-budget advisory, daemon down.

The log must let both the user and a post-hoc agent tell these apart in one look.

## What exists today (the seed, not the answer)

`~/.warden/hook.log` — timestamped single-line entries from the dispatchers: `FIRED <moment> @ <anchor> traits=[…] → N steer(s)`, `AUDIT-ON-WRITE <file> @ <anchor> → N issue(s)`, `OVER-BUDGET <moment> fired in X ms`, and error notes. Gaps: no steer/deny **text** (you can't see what the agent was told), no **considered-but-didn't-fire** record (cause 1 is invisible), no **suppression** record (cause 4 is invisible), no session/turn correlation, no query surface (raw tail is the only reader), no retention policy.

## Design sketch (to be settled during build)

- **One event record per moment fire**, structured (JSONL beside the current log?): timestamp, session, moment, governing anchor + effective traits, rules selected, per-rule outcome (`fired` / `guard-false` / `throttled` / `deduped` / `denied` / `error`), and the **emitted text verbatim** for anything that reached the agent.
- **A "why" query surface** — plausibly `warden log` CLI verbs (`warden log tail`, `warden log why <file-or-moment>`, `warden log session <id>`) so the *agent* can answer "what did Warden tell me this session?" without the user grepping.
- **Capture cost discipline** — the hot path is ~3 ms; logging must stay append-only and defer any formatting; consider sampling for no-fire moments (the considered-set can be huge) vs. full fidelity for fires/denies/suppressions.
- **Retention** — size-capped rotation in `~/.warden/`; the log is diagnostic, not archival.

## Status

**Ready** — commissioned with an explicit user goal; the design forks above are agent-decidable engineering choices (log shape, CLI verbs, rotation), to be settled against the PRD goal during the build and reviewed on the live artifact.
