- **T019 — R-markdown-05 em-dash fixer corrupts code; three defects, all reproduced** [Done 2026-08-11] — **Moved to [[TINK Backlog#^T222|TINK T222]] 2026-08-11** when this queue was retired; the live record and all further work are there. Original body preserved on the new row. ^T019
  - **Next:** teach `_repl_outside_code` to mask 4-space indented code blocks; repoint `chk_md_em_dash` at it so one predicate serves both; make the fixer skip lines with odd backtick parity and warn instead; add corpus cases asserting a spaced double-hyphen survives untouched inside indented blocks, fenced blocks, and a line with unbalanced backticks; re-run the Warden corpus.
    - Found 2026-07-30 authoring [[F286 — Chokepoint interfaces — declared in Architecture, compile-enforced, graded exceptions|SKA F286]]. The on-write fixer silently rewrote a spaced double-hyphen to an em-dash **inside a 4-space indented code block**, turning a git pathspec separator into an em-dash and leaving a valid-looking but broken command that would have shipped to another agent as instructions. Investigation found three distinct defects in [audit-plan.py](~/.claude/skills/audit/scripts/audit-plan.py).
    - **Defect 1 — indented code blocks are not treated as code.** Both `chk_md_em_dash` and `_repl_outside_code` mask fenced blocks and inline code spans, but neither recognizes the 4-space-indented code block, which is legal Markdown and is used throughout these design docs. [[R-markdown]]-05's own text scopes the rule to "a definition-list bullet (or prose)" and already exempts flag-style and horizontal-rule forms, so rewriting inside a code block is outside its stated intent — a scope bug, not a judgment call.
    - **Defect 2 — checker and fixer each define "outside code" independently, and disagree.** `chk_md_em_dash` hand-rolls its masking inline while `fix_md_em_dash` delegates to `_repl_outside_code`; the two inline-span character classes differ (the checker's excludes only newline, the helper's excludes newline **and** backtick), so on a line with several spans they mask different regions. The checker can therefore report clean while the fixer still rewrites, and no test catches it because each is internally consistent. Fix: the checker calls the shared helper — the same "port, don't re-derive" discipline already written into `_ends_with_terminal_link` a few functions above it.
    - **Defect 3 — backtick-parity failure makes the escape hatch unreliable (reproduced live).** A code span whose *content* contains a backtick — unavoidable when documenting regexes, Markdown, or nested shell — breaks the naive paired-delimiter matching, and **everything after it on that line silently loses its masking**. Proof: the first draft of this very row was corrupted by the rule it describes. A span reading backtick-space-double-hyphen-space-backtick was converted to an em-dash *despite being inside backticks*, because the line carried 19 backticks (odd parity) after a triple-backtick appeared inside a single-backtick span. So "put commands in backticks" is a good convention but NOT a sufficient defense.
    - **Design implication — auto-fixers must be conservative under ambiguity.** A fixer that cannot determine masking with certainty must **refuse to fix and report instead**; silently rewriting content it does not understand is strictly worse than leaving a lint finding. Concretely: on odd backtick parity in a line, skip the line and emit a warning. Silence beats corruption, especially for a fix that runs unattended on every write.
    - **Why this matters beyond the bug:** `_repl_outside_code` is a textbook **chokepoint** — the single place answering "what counts as code" — and it is bypassed by its own paired checker. This is a live in-house instance of exactly the failure [[F286 — Chokepoint interfaces — declared in Architecture, compile-enforced, graded exceptions|SKA F286]] is being built to prevent, and a strong first candidate for that feature's adoption scan.
